你现在是一名Markdown规范检查工具开发者。请帮我编写一个文档格式标准化脚本：

【任务描述】对Markdown文件进行格式标准化处理，使其符合统一的编写规范。

【输入信息】Markdown文件

【处理规则】
1. 标题标准化：确保标题前后各有且仅有一个空行，#号后统一为一个空格；
   删除标题行尾部的锚点属性（如 {#xxx}）；不改变原有标题层级（# 的数量）。

2. 列表标准化：无序列表标记统一为 -；有序列表保留原编号或按 1.2.3. 自动重排；
   列表项缩进统一为两个空格。

3. 删除冗余内容，按以下可判定特征逐项清理：
    - HTML注释（<!-- ... -->）、内联 style 标签、空链接 [text]()；
    - 连续空行合并为一个，去除文件首尾多余空行、行尾多余空格；
    - 【重点】孤立的表格残留符号：凡满足"该行去除空白后仅剩竖线与空格"
      （如 |、| |、|  | |、由多个空单元格构成的行），且不属于下方第4条判定的
      真实表格块，一律视为无效符号删除；
    - 单元格内部的成对空竖线（如 "| |" 这种空占位）出现在正文行/标题行末尾时，
      仅裁剪该行尾部残留竖线，保留前面的有效正文文字。

4. 表格/代码块/引用块的"真伪判定与保留"边界（必须先识别再保护）：
    - 真实表格定义：连续的、以 | 开头的行，且紧随其后存在合法分隔行
      （形如 |---|---| 或 |:--|--:|，列数与表头一致）。只有满足此条件的整块
      才按原格式保留，不得改动其内部单元格、续行（\）与合法占位空单元格。
    - 不满足上述条件的孤立 | 行（如夹在标题与正文之间、或正文行后单独出现的
      "| |"），判定为残留噪声，交由第3条删除，禁止当作表格保留。
    - 代码块（``` 或 4空格缩进）与引用块（>）内部内容一律原样保留，
      其中出现的 | 不参与上述删除逻辑。

【输出要求】将标准化后的文件覆盖原文件，并逐条输出"修改了哪些行、属于哪条规则"
的日志（含行号、修改类型、修改前后片段）。

【代码约束】代码轻量简洁，逐行处理或使用 markdown-it-py 等轻量库；
务必先做"表格块边界识别"再执行清理，确保处理速度快且不误删真实表格。
